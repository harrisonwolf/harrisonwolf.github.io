01Systems

Neighborhood-intelligence engine

six-source pipeline with a separate serving runtime
Python · core in ~3 months · private repo — walkthrough on request

On screen, an agent workspace for choosing a neighborhood — parcels, schools, safety, and market layers over Fresno County. That's the tip of it. Underneath is an 8-stage pipeline that pulls from six external sources — county GIS, schools, market data — normalizes everything into one canonical schema, scores it with Bayesian shrinkage throughout, and publishes frozen, versioned bundles that a separate 14-table runtime serves; every number still traces back to its source file. What that discipline buys is concrete: the serving layer can only name 12 tables from an allowlist, scoring refuses to run on data normalized by older code, and the runtime refuses a bundle whose payload version doesn't match — those version mismatches raise an error instead of quietly shipping. A path-traversal hole in static file serving was caught this way and closed with a regression test that fails if it ever comes back. Multi-county spin-up is built and tested; it currently runs at one county. I designed the architecture, schema, scoring, and test gates; coding agents produced most of the implementation under a written rulebook.

Algebra search engine

70–115× faster than Macaulay2
C++ · hand-written core · repo · arXiv:2512.24320

Sifts tens of billions of algebraic structures for the rare ones that break a proposed rule. I wrote the ~1,200-line C++ core by hand in 2024 and validated it case-by-case against Macaulay2, the standard tool for this work. Its exhaustive search surfaced the counterexamples behind one of the paper's three main theorems. On matched searches across codimensions 3–7 it runs 20.7 million candidates in 11 seconds, versus ~17 minutes in Macaulay2.

Video generation on an 8 GB GPU

two open-weight models, one 8 GB card
Python · core in ~2 weeks · repo

Runs two open-weight video models on a single 8 GB GPU and chains short shots into longer clips that stay coherent, driven from a terminal UI. A resident vision-language model (Qwen3-VL, 4-bit) turns plain-language direction into runnable generation settings. The measurement layer includes seam and drift telemetry plus a blind A/B harness. Drift control between shots uses AdaIN latent anchoring (from diffusers, cited) and a custom color-matching pass. I built the orchestration, UI, and measurement; the generation models use published open weights.

Geometry engine from first principles

The geometry behind games and maps
C++ · hand-written · nothing beyond the standard library · repo

Delaunay and Voronoi, plus the geometric predicates under them, built for fun from a bare terminal in vim and make: polygon construction and generation, point-in-polygon and collision queries, ear-clipping, and local SVG and Desmos viewers. The hard part is robustness: the predicates handle collinear inputs, duplicate points, and orientation with explicit epsilon handling, verified by a hand-rolled TDD harness of 13 suites.

02Applied demo

Terrain studies

Geometry engine + GIS platform · portfolio demonstration · full case study

A study a landowner or agency would normally pay a survey crew and a consultant for. These preliminary estimates use free public data at three Central California sites. The geometry engine triangulates each surface from public USGS elevation; the Nexora platform can supply a real parcel boundary. Neither was built for terrain work. Each surface is a Delaunay TIN over USGS 3DEP 10-meter elevation, and reservoir volume is integrated off the resulting stage–storage curve — resolution enough to scope a site, not to design one.

  • A level building pad on a sloped lot, cut balancing fill: 9,160 cubic yards moved.
  • A 22.2-acre bluff's rainfall routed (604k gal from a one-inch storm): which slopes shed, where the water collects, where it leaves the property.
  • A dry canyon dammed at its one outlet: 44,457 acre-feet below the 329-meter waterline, about 14.5 billion gallons, closed by a 256-foot dam.

A real siting study still needs calibrated models and a licensed engineer. The harness lives in its own repo now; contact me for more.

03How I work

On compact problems, I keep the implementation small enough to reason about directly and build measurements around the parts most likely to fail. On larger work, I define the architecture, interfaces, and acceptance tests before directing agent implementation, then review the result against those artifacts. The C++ cores here are hand-written. The neighborhood platform was implemented mainly by coding agents; each project identifies the use of external models, algorithms, or collaborators.
