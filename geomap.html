Nexora ranks Fresno County neighborhoods against a family’s budget and priorities, from six public sources that never agreed on a format. Every number on screen traces back to a versioned data bundle, and thin evidence is pulled toward neutral instead of overclaimed.

Why it exists

A ranking is only worth trusting if every number has a source.

Choosing where to live means weighing schools, safety and prices from sources that differ in format, geography and update schedule, and many neighborhoods have too little data for a plain average to be trusted. Nexora is not a pipeline bolted onto an existing county viewer. I designed and built the whole system from scratch, from the data architecture to the map interface, orchestrating coding agents for most of the implementation.

  • Six sources, one schema.County GIS, market data, two school datasets, attendance boundaries and a safety baseline become 53 canonical tables.
  • Eight stages, one command.Extract to serve, re-runnable end to end; refreshing a county is make refresh-county.
  • 948 tests.Pipeline, scoring math, HTTP surface and concurrency, including simultaneous requests at a report quota.
  • Honest on thin data.Estimates shrink toward neutral in proportion to sample support; where coverage is too thin the score is suppressed, not faked.
The picker

What a buyer’s agent sees.

An agent describes the family once. Hard constraints filter the county, soft preferences weight what’s left, and the result is a ranked shortlist with plain-language reasons the agent can hand to a client.

01 · Shortlist

Every card carries its evidence.

Assigned schools with scores, safety relative to the county median, typical home price against the family’s range, and the caveats: a neighborhood that straddles two attendance boundaries says so on the card. One click turns the shortlist into a share link or a print-ready PDF.

02 · Parcels

Down to the street, and one parcel open.

Zoom in and every dot is a real parcel on a named street. Open one and you get its APN, neighborhood cell and modeled price, with the data-quality label right beside the number.

03 · Lineage

Published values keep their source.

Each artifact records its source, acquisition time, code version and SHA-256 fingerprint, and every adapted artifact points back to the exact raw batch it came from. A version mismatch anywhere refuses to load; there is no silent legacy fallback.

The engine

Eight stages between a county website and a ranked answer.

Data moves one direction through hard boundaries. Source quirks die in the first two stages, scorers only ever see canonical facts, and the web runtime only ever reads frozen, versioned bundles. No stage can peek upstream.

  1. ExtractPayloads pulled from county GIS services and public datasets, SHA-256-fingerprinted on arrival.
  2. AdaptEach source family becomes a structured, versioned artifact. Downstream code never sees a source’s file format again.
  3. NormalizeAdapted records land in canonical tables, stamped with the normalizer version that produced them.
  4. SnapshotFor a county and month: clipped polygons, hex-cell grids, attendance overlaps, computed once and frozen.
  5. ScoreMarket state per hex cell; schools and safety per neighborhood. Bayesian shrinkage throughout.
  6. PublishA self-contained, versioned bundle: manifest, payloads, map thumbnails, tracked in a publication index.
  7. BootstrapThe 14-table runtime database is rebuilt from the latest bundle. A version mismatch refuses to load.
  8. ServeA lightweight runtime ranks against each family’s preferences live, and renders the map, share links and PDFs.
Below the waterline

Built into the engine, not yet in the picker.

The family picker deliberately shows a fraction of what the platform computes. The rest is implemented and tested, one toggle or one data feed away.

  • Hex-cell market heat map.Value, tightness, trend and acceleration scored per cell across the county, served whole on every page load; an investor’s layer, dark by default in the family product.
  • Parcel-level inspector.Parcel geometry with APN, address and sale history behind a disabled map layer.
  • New-county spin-up.Registry-driven boundary validation, ZIP baselines and GIS profiles without changing engine code. Fresno is the only county run end to end.
  • A slider withheld on purpose.The UI collects commute constraints, and the easy move was to zero-fill the data and ship a commute weight anyway. The slider is pinned to zero in code until real commute data lands.

Discipline: fail-closed gates, shrinkage, atomic quotas

Fail-closed version gates. The scoring path rejects data normalized by an older schema version; the runtime rejects bundles with a mismatched payload version and reports the mismatch.

Shrinkage on thin data. Estimates shrink toward neutral in proportion to sample support, n / (n + k); where coverage is too thin the score is suppressed outright.

Atomic report limits. Per-agent report quotas use a single guarded insert, covered by a two-thread test that fires simultaneous requests at the limit.

Agent workflow. Coding agents worked across git worktrees under a written rulebook; every merge had to pass the project’s tests and review gates.

Known limits

Data staleness at serve time warns the operator but doesn’t block serving; keeping data fresh is left to the operator. Multi-county support is tested but has never run against more than one county for real. Bundle versioning catches version mismatches, but a payload shape change within a version would slip through, a known gap flagged in the repo’s own docs. The map displays precomputed scores and the county’s official GIS layers; a time-series interface over the retained monthly vintages is not implemented.

The public Audit Edition

The product repository is private. The Nexora Audit Edition is a synthetic, executable extraction of five reliability mechanisms and their tests, released under AGPL-3.0 for independent inspection. I directed the extraction and adversarial review; coding agents produced most of the implementation under executable tests and release gates. Version 0.1.1 includes the tests, machine-readable claims, source map, known limitations and correction record, but no product interface, real data, production configuration or private history.
